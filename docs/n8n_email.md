# Отправка документов через n8n (на том же сервере)

Хостеры часто блокируют исходящий SMTP (порты 25/465/587), из-за чего бот не может
слать письма напрямую. Решение: бот POST-ит письмо в **вебхук n8n**, а n8n
отправляет его своей нодой (SMTP-релей, Gmail и т.п.). Так вся отправка документов
идёт единообразно через n8n, который поднят рядом в том же `docker compose`.

Через n8n уходят все документы, которые формирует бот:

| Документ | Откуда | Как формируется |
|----------|--------|-----------------|
| **УПД по аренде** (PDF) | `/admin → 📧 УПД аренда` | `document_service.upd_email_package(..., ChargeType.rent)` |
| **УПД по электричеству** (PDF) | `/admin → 📧 УПД электричество` | `document_service.upd_email_package(..., ChargeType.electricity)` |
| **Квитанция на оплату аренды** (PDF) | `/admin → 📧 Квитанция`, а также авто-рассылка (счёт/напоминание/просрочка) | `document_service.receipt_email_package` / `document_service.receipt_pdf` |

Все три пути в итоге вызывают `app/email/sender.py::send_email`, а при
`EMAIL_PROVIDER=n8n` — транспорт `_send_n8n`, который и общается с n8n.

---

## 1. Что бот отправляет в n8n (контракт вебхука)

`POST` на `EMAIL_N8N_URL` (например `http://n8n:5678/webhook/send-email`),
`Content-Type: application/json`. Если задан `WEBHOOK_TOKEN` — добавляется
заголовок `X-Webhook-Token: <токен>` (можно проверять в n8n).

```json
{
  "to": "tenant@example.ru",
  "subject": "УПД № УПД-Э-17/2024-АР/09-26 по договору аренды № 17/2024-АР",
  "text": "Здравствуйте, ООО «Ромашка»! ...",
  "from": "owner@example.ru",
  "meta": {
    "document_type": "upd",
    "kind": "electricity",
    "number": "УПД-Э-17/2024-АР/09-26",
    "tenant_name": "ООО «Ромашка»",
    "tenant_email": "tenant@example.ru",
    "contract_no": "17/2024-АР",
    "period": "2026-09",
    "period_human": "сентябрь 2026 г.",
    "amount": "3 450.00",
    "landlord_name": "ИП Иванов И.И."
  },
  "attachments": [
    { "filename": "УПД-Э-17-2024-АР-09-26.pdf", "mime_type": "application/pdf", "content_base64": "<...>" }
  ],
  "filename": "УПД-Э-17-2024-АР-09-26.pdf",
  "pdf_base64": "<...>"
}
```

- `attachments` — основной список вложений (может быть несколько PDF).
- `filename` / `pdf_base64` — дублируют **первое** вложение для простых воркфлоу
  «одно письмо — один PDF».
- `meta` — метаданные документа (тип, арендатор, договор, период, сумма), чтобы
  в n8n можно было маршрутизировать/логировать письма и не парсить тему руками.

Ответ n8n — любой из `200/201/202/204`. Тело не обязательно.

## 2. Поднять n8n на том же сервере

n8n уже описан в `docker-compose.yml` (сервис `n8n`, порт `5678`, том `n8n_data`).

```bash
git fetch origin && git checkout claude/migration-service-error-1bjg1w && git pull
docker compose up -d n8n
```

Задайте в `.env` (см. `.env.example`):

```dotenv
# n8n за реальным доменом/через reverse-proxy — укажите свой хост
N8N_HOST=n8n.example.ru
N8N_PROTOCOL=https
N8N_USER=admin
N8N_PASSWORD=надёжный-пароль
```

Откройте UI: `http://<сервер>:5678` (логин/пароль из `N8N_USER/N8N_PASSWORD`).
Бот и n8n в одной сети compose, поэтому бот ходит к n8n по внутреннему адресу
`http://n8n:5678` — наружу порт открывать не обязательно.

---

## 3. Импортировать готовый воркфлоу

1. В n8n: **Workflows → ⋯ (три точки) → Import from File**.
2. Выберите `app/email/n8n_send_email.workflow.json` из репозитория.
3. Воркфлоу состоит из узлов: **Webhook** (`POST /webhook/send-email`) →
   **Подготовить письмо** (Code: раскладывает `attachments` из base64 в бинарные
   вложения) → **Отправить письмо (SMTP)** → **Ответить боту**.

---

## 4. Настроить отправляющую ноду

Узел **«Отправить письмо (SMTP)»** требует SMTP-credential в n8n:

1. **Credentials → New → SMTP** и заполните хост/порт/логин/пароль своего почтового
   релея (или Gmail App Password, `smtp.gmail.com:465`, SSL/TLS on).
2. Откройте узел «Отправить письмо (SMTP)» и выберите созданный credential
   (в JSON стоит заглушка `REPLACE_WITH_YOUR_SMTP_CREDENTIAL_ID`).
3. Поле **From** берётся из `{{$json.from}}` (т.е. из `EMAIL_FROM` бота); при желании
   зафиксируйте адрес отправителя прямо в узле.

> Вместо SMTP-узла можно поставить узел **Gmail** (OAuth2) или узел вашего
> провайдера — вход остаётся тем же (`to`, `subject`, `text`, бинарные вложения
> `attachment_0…`). Именно ради обхода блокировок SMTP n8n и используется: у него
> может быть свой доступ к почте/relay, недоступный боту напрямую.

Нажмите **Save** и активируйте воркфлоу тумблером **Active** (иначе работает только
тестовый URL `/webhook-test/...`).

---

## 5. Прописать транспорт в боте

В `.env` бота:

```dotenv
EMAIL_PROVIDER=n8n
EMAIL_N8N_URL=http://n8n:5678/webhook/send-email
EMAIL_FROM=owner@example.ru
# необязательно — общий секрет, уходит в заголовке X-Webhook-Token
WEBHOOK_TOKEN=любой-длинный-секрет
```

Перезапустите бота:

```bash
docker compose up -d --build bot
```

---

## 6. Проверка

1. `/admin → 🔌 Тест почты (без отправки)` — покажет, что транспорт `n8n` настроен
   и виден URL вебхука.
2. `/admin → 🧪 Заполнить тестовыми данными` (если данных ещё нет), у арендатора
   должен быть указан email.
3. `/admin → 📧 УПД аренда` / `📧 УПД электричество` / `📧 Квитанция` → выберите
   арендатора. Бот сформирует PDF и отправит его в n8n; n8n доставит письмо.
4. В n8n на вкладке **Executions** видно каждое обращение и результат отправки —
   удобно для отладки.

### Частые ошибки

- **404 от вебхука** — воркфлоу не активирован (кнопка **Active**) или путь отличается
  от `send-email`. Сверьте `EMAIL_N8N_URL`.
- **Письмо ушло без вложения** — проверьте, что в узле SMTP в
  `Options → Attachments` стоит `={{$json.attachmentProps}}`, а узел «Подготовить
  письмо» отработал (в Executions видно бинарные `attachment_0…`).
- **`EMAIL_N8N_URL не задан`** — не заполнена переменная в `.env` бота.
- **Таймаут/Network unreachable у самой SMTP-ноды** — значит и у n8n нет прямого
  SMTP-доступа; используйте почтовый API/Gmail-ноду в n8n.
