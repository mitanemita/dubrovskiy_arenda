# План: карта базы из БД в разделе «📊 Отчёты»

Цель: в отчётах бота кнопка **«🗺 Карта базы»** — бот собирает HTML-карту из актуальных
данных PostgreSQL и присылает файл. Сохраняются принципы карты и принципы бота.

**Принципы карты** (`app/karta/karta.py`):
- в странице нет исполняемого JS;
- данные лежат в JSON внутри страницы;
- цвет, бейдж, площади и суммы считаются при сборке.

**Принципы бота** (из `HANDOFF.md` рабочей ветки `claude/migration-service-error-1bjg1w`):
- в чате одно сообщение-панель, бот его только редактирует;
- сообщения пользователя удаляются сразу после ввода;
- вся навигация на инлайн-кнопках;
- занятость помещения определяется автоматически по договору.

Решения, принятые по ответам:

| Вопрос | Решение |
|---|---|
| Цвет литеры | есть арендатор → 🔵 «Арендовано»; нет арендатора и готово → 🟢 «Свободно»; нет арендатора и **не готово** → 🟠 «Не готово» (оранжевый `#e8a020`). Стройка, «Не сдаётся», технические — только вручную |
| Договоры | есть, но в бот ещё не занесены → на старте арендатор и рента литеры хранятся в полях самой литеры. Как только по литере заведён договор, данные берутся из договора |
| Фактическая рента | сколько арендатор платит **за само помещение** (без электричества и пени) = `Lease.rent_amount` |
| Ссылка на «живую» карту | не делаем: её нельзя получить без публичного адреса сервера. Карта приходит **файлом в чат**. Ссылка Artifact на claude.ai обновляется вручную из чата с Claude |
| Админ-меню без проверки доступа | пока оставляем, бот в разработке |

---

## 1. Как устроен бот сейчас (то, на что опираемся)

- **Одна панель.** `_PANELS[chat_id]` хранит id активного сообщения бота.
  - `edit_or_send(message, text, kb)` правит его в callback-ах;
  - `wiz_reply` правит панель по id при вводе текста;
  - `send_panel` создаёт панель (`/menu`, `/start`).
- **Удаление ввода.** `FSMCleanupMiddleware` (`app/bot/runner.py`) удаляет сообщение
  пользователя, если оно пришло во время мастера (FSM).
- **Отчёты.** `menu:reports` → `_show_report_main` (сводка за месяц) → `rep:prem` / `rep:elec` /
  `rep:debt` / `rep:years`, возврат «◀️ К сводке» и «◀️ В меню».
- **Помещения.** `premises` (`label`, `address`, `area`, `is_occupied`). `is_occupied`
  выставляет `directory_service._sync_occupancy` по активным договорам.
- **Аудит.** Таблица `adjustments` (кто, поле, старое и новое значение, причина).
- Последняя миграция — `0006_task_assignee`.

**Ограничение Telegram, которое надо учесть.** Текстовое сообщение нельзя превратить в
документ. Поэтому, чтобы прислать файл и оставить в чате одно сообщение, бот:
1. отправляет документ;
2. удаляет прежнюю панель;
3. делает документ новой панелью.

Обратный переход (из документа в текстовый экран) работает так же. Документ при этом
**можно** заменить на месте: `edit_message_media` подходит для кнопки «🔄 Обновить».

## 2. Данные литер в БД

Литера уже хранится в БД: колонка **`premises.litera`** (миграция `0007_premises_litera`).
- Свободный текст до 32 символов, со списком карты не сверяется: у другой базы свои литеры.
- При добавлении арендатора в помещение (мастер договора) литеру указывают **обязательно**:
  можно оставить текущую литеру помещения или ввести другую.
- Карта сопоставляет помещение с контуром на плане по `premises.litera`, а не по названию.
  Литеры, которых нет на этом плане (другая база), в сводке идут как «нет на плане».

Для карты (миграция `0008_premises_card`) добавляем колонки:

```text
premises (+)
  kind         text null          -- 'tech' для T1–T9
  floors       text not null default '1'   -- '1' | '2' | '1,2'
  status_lock  text null          -- closed | build | tech; NULL = цвет считается автоматически
  badge        text null          -- свой текст бейджа (пока статус тот же)
  hint         text null          -- «Не описано.», «Помещение без литеры.»
  state, comm, doors, purpose, look, ready   text null
  rate         numeric(10,2) null -- ставка ₽/м²
  rate_text    text null          -- ставка словами («Не оценено»)
  tenant_note  text null          -- арендатор, пока нет договора в боте
  rent_fact    numeric(12,2) null -- факт. рента, пока нет договора в боте
  rooms_count  int null           -- если нет списка помещений (area уже есть)

premises_rooms (новая)
  id, premises_id FK → premises ON DELETE CASCADE,
  pos int, area numeric(10,2), note text null, floor int null,
  UNIQUE(premises_id, pos)
```

**Откуда что берётся при сборке:**

| Поле карты | Источник (по приоритету) |
|---|---|
| Арендатор | 1) `Tenant.name` активных договоров (через запятую); 2) `premises.tenant_note`; 3) «Нет» |
| Фактическая рента | 1) сумма `Lease.rent_amount` активных договоров; 2) `premises.rent_fact`; 3) «—» |
| Помещения, площадь | `premises_rooms` (сумма) или `premises.area` + `rooms_count` |
| Статус / цвет | **не хранится**, кроме `status_lock`. Считает `karta.compute_status` по правилу из таблицы выше |
| Стоимость в месяц, фактическая ставка | считает `karta.py` (площадь × ставка; рента ÷ площадь) |

Связь с автоматической занятостью: `is_occupied` по-прежнему ставится от договоров. Карта
считает литеру занятой, если `is_occupied` **или** заполнен `tenant_note`. При заведении
договора `tenant_note` и `rent_fact` можно очистить: данные уже идут из договора.

## 3. Первичное наполнение — `app/scripts/import_karta.py`

Команда:
```bash
docker compose run --rm api python -m app.scripts.import_karta app/karta/Karta-krasnodar.html
```

Скрипт запускается один раз; повторный запуск ничего не дублирует.
- Читает JSON карты (`karta.load`).
- Находит или создаёт `premises` по `litera` и заполняет описание и `premises_rooms`.
- `tenant` переносит в `tenant_note`, только если по литере нет активного договора.
- `rent_fact` переносит в `premises.rent_fact`.
- Статусы closed, build, tech переносит в `status_lock`.
- Если в справочнике уже есть помещение с другим названием (например, из демо-данных),
  ничего не удаляет, только выводит его в отчёте.

**Критерий приёмки** (тест на SQLite): импорт → сборка из БД → файл **побайтно равен**
`app/karta/Karta-krasnodar.html`.

## 4. Сервис `app/services/karta_service.py` (без Telegram)

```python
async def build_data(session, landlord_id) -> list[dict]          # БД → JSON формата karta.py
async def render_html(session, landlord_id) -> tuple[bytes, dict]  # файл + сводка
```

- Шаблон — `app/karta/Karta-krasnodar.html` (картинки, контуры, CSS). Данные подставляет
  `karta.apply`, тот же код, что в CLI. Правило цвета одно на всё.
- Порядок литер берётся из шаблона. Помещения без контура на плане попадают в сводку как
  «нет на плане».
- Сводка для подписи:
  - сколько литер арендовано, свободно, не готово;
  - общая площадь и площадь в аренде;
  - сумма фактической ренты и число литер без суммы.
- `karta.check(data)` проверяет данные; при расхождении — запись в лог и «⚠️» в подписи.
- Сборка занимает около 10 мс. Файл нигде не хранится и каждый раз собирается заново из БД.

## 5. Бот: «📊 Отчёты» → «🗺 Карта базы»

### 5.1 Кнопка
В `_report_nav_kb` добавляется строка `[🗺 Карта базы]` с callback `rep:map`.

### 5.2 Одна панель
Новые хелперы в `handlers_admin.py`, рядом с `edit_or_send`:

```python
async def show_document_panel(message, file: BufferedInputFile, caption, kb):
    """Документ становится панелью: отправить → удалить старую панель → _set_panel(док)."""

async def replace_panel(message, text, kb):
    """Текстовый экран вместо документа: отправить текст → удалить документ → _set_panel."""
```

Небольшая правка `edit_or_send` и `wiz_reply`. Если править нечего (панель — документ,
у неё нет текста), сейчас отправляется новое сообщение, а документ остаётся в чате. После
правки старая панель **удаляется**. Тогда любая кнопка из любого раздела оставляет в чате
одно сообщение.

### 5.3 Экраны

```text
📊 Сводка за Ноябрь 2026            ← панель (текст)
  [🏠 По помещениям] [⚡ Электричество]
  [🔴 Должники] [📅 Другой месяц]
  [🗺 Карта базы]
  [◀️ В меню]
        │ rep:map
        ▼
⏳ Собираю карту…                   ← та же панель (edit)
        ▼
📎 Karta-2026-11-12.html             ← документ стал панелью, текст удалён
  🗺 Карта базы на 12.11.2026 14:05
  🔵 Арендовано 24 · 🟢 свободно 9 · 🟠 не готово 5
  Фактическая рента: 312 000 ₽ (нет суммы у 18 литер)
  [🔄 Обновить] [◀️ К сводке] [◀️ В меню]
```

- `rep:map:refresh` пересобирает карту и заменяет файл в том же сообщении
  (`edit_message_media`, `InputMediaDocument`).
- «◀️ К сводке» (`rep:main:<код>`) и «◀️ В меню» (`nav:home`) возвращают текстовый экран:
  через `edit_or_send` с удалением документа (п. 5.2).
- Ввода текста в этом разделе нет, удалять нечего. Если пользователь всё же что-то
  напишет, сообщение удалит `FSMCleanupMiddleware`, как и сейчас.
- Файл: `BufferedInputFile(html, filename=f"Karta-{дата}.html")`, около 1,1 МБ (лимит
  Telegram — 50 МБ). На телефоне открывается в браузере: Safari 15.4+, Chrome 105+, JS не нужен.
- Поднять `BOT_UI_VERSION`.

## 6. Следующий этап: правка литер в боте

Вход: «🗂 Справочники» → «🏢 Литеры», или кнопка «✏️ Литера» в разделе карты.
Шаги: этаж → литера → поле → значение. Всё в одной панели: выбор кнопками, ввод через
`wiz_reply`, введённое сообщение удаляется.

- Поля:
  - кнопками: готовность («Готов» / «Не готов» / свой текст), состояние, внешний вид;
  - вводом: коммуникации, ставка, `tenant_note`, `rent_fact`.
- Когда договор заведён, арендатор и рента меняются только через договор. Бот покажет:
  «берётся из договора №…».
- Каждая правка пишется в `adjustments` (`entity_type='premises'`, поле, старое и новое
  значение, пользователь).
- После сохранения панель показывает карточку литеры (`karta.summary`):
  - пересчитанные стоимость в месяц и фактическую ставку;
  - новый цвет;
  - кнопку «🗺 Карта» для свежего файла.

## 8. Порядок работ

1. ✅ Литера в БД и в мастере договора (`0007_premises_litera`).
   ✅ Кнопка «📊 Отчёты → 🗺 Карта базы» (`karta_service`, `rep:map`, `rep:mapre`). Пока описания литер
   берутся из шаблона карты, а арендатор и фактическая рента — из активных договоров по `premises.litera`;
   литеры без договора показываются как в шаблоне. Дальше — перенос описаний в БД (п. 2–4).
2. Миграция `0008` + модели `Premises` и `PremisesRoom`.
3. `import_karta` + тест побайтного равенства.
4. `karta_service` + тесты правил цвета и ренты.
5. Хелперы панели-документа, правка `edit_or_send` и `wiz_reply`, кнопка `rep:map`.
   Поднять `BOT_UI_VERSION`.
6. Выкатка:
   ```bash
   git pull && docker compose up -d --build
   ```
   затем один раз `import_karta`.
7. Следующий этап — правка литер в боте (п. 6).
